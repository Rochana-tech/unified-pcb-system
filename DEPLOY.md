# Public review deployment

The Python backend, ANN, WebSockets and 3D dashboard run together. Visitors can view the shared simulation. Operator access is required to reset it, inject faults, confirm repairs or run comparisons.

## Render setup

1. Push the prepared changes to GitHub. The prepared repository puts this app in the unified-system subfolder and points its root render.yaml there.
2. Sign in to https://dashboard.render.com with GitHub.
3. Choose **New → Blueprint**, connect **Rochana-tech/Digital_Twin**, and select the deployment branch containing the new root render.yaml.
4. Confirm the **Free** plan and apply the blueprint.
5. Wait for the build and health check. Open the service's public HTTPS URL ending in .onrender.com.
6. Reveal the generated **OPERATOR_KEY** in Render's Environment settings. Enter it through **Operator access** in the dashboard. Do not put the key in GitHub, a screenshot, a URL or chat.

The render.yaml inside this folder is for a repository whose root contains these app files. The prepared repository's root manifest instead sets rootDir to unified-system.

## Free demo limitations

Free services can sleep when idle and take about a minute to wake. Local SQLite history disappears on restart, redeploy or sleep. Runtime WIP, routes and timers also start a new session on restart. This configuration is for a review demonstration.

Persistent logs require suitable persistent storage, for example a paid service with a disk at /app/data. No paid resource is enabled by this manifest.

## Configuration

- PUBLIC_DEPLOYMENT=1 enables protected controls and restricts public hosting to demo data.
- OPERATOR_KEY is generated by Render; at least 24 characters.
- HOST=0.0.0.0 binds the hosting interface.
- PORT is supplied by the host.
- DATABASE_PATH=/app/data/manufacturing.sqlite3
- Use one process and one instance: simulation state is in memory.
- Health check: /api/health.
- WebSockets use WSS automatically over HTTPS.
- ANN artifacts and Three.js files are bundled locally.

The local Windows launch is unchanged and does not require an operator key. Never publish with PUBLIC_DEPLOYMENT=0.
